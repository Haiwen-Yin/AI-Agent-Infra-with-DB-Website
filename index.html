Graph Engineering in This Project本项目中的图工程
Graph Definition describes versioned nodes, edges, capabilities, and policies; Graph Version freezes an immutable executable model; the Compiler turns that model into a deterministic Compiler Plan; and Graph Run executes the plan as a durable, observable run. The relational database persists Runs, Checkpoints, Worker Leases, Events, and Artifacts, so execution can resume, be inspected, and be governed after retries or process failures. Property Graph supports relationship exploration, while the Execution Graph defines how work is compiled and run. Graph Engineering coordinates multiple Loops, nodes, events, and external capabilities through one runtime boundary. Oracle, PostgreSQL, and YashanDB are adapted behind the same contract. In v4.3.0, Graph Preview remains an explicitly gated experimental capability and retains flexibility as engineering practices and industry conventions evolve.Graph Definition描述版本化的节点、边、能力与策略；Graph Version冻结不可变的可执行模型；Compiler将模型转换为确定性的Compiler Plan；Graph Run则按照计划执行一次持久化且可观测的运行。关系型数据库持久化Run、Checkpoint、Worker Lease、Event与Artifact，使执行在重试或进程异常后能够恢复、检查与治理。Property Graph负责关系探索，Execution Graph负责定义工作如何编译与运行。Graph Engineering通过统一运行时边界协调多个Loop、节点、事件与外部能力。Oracle、PostgreSQL与YashanDB均在同一契约之后完成适配。在v4.3.0中，Graph Preview仍是显式受控的实验能力，并会随工程实践与行业规范演进保持灵活性。

Graph Engineering: the next layer above Loop图工程：位于循环工程之上的下一层
Graph Engineering turns a multi-Agent workflow into a versioned, inspectable, durable execution graph. Definitions, compiled plans, Runs, Checkpoints, Events, Workers, collaboration gates (Barrier), interventions, and evidence are persisted in the database. A Graph can compose and pause Loops, narrow authority at each node, wait for human or Agent arrivals, and resume or fork from a checkpoint. The v4.3.0 production profile contains the validated stable core; Graph Preview remains an explicit experimental capability while the engineering model evolves.图工程将多Agent工作流变成版本化、可检查、可持久恢复的执行图。定义、编译计划、运行、检查点、事件、Worker、协作关卡（Barrier）、干预与证据均持久化在数据库中。Graph可以组合并暂停Loop，在每个节点收窄权限，等待人或Agent到达后继续，或从检查点恢复/分叉。v4.3.0的production profile包含已验证的稳定核心；Graph Preview仍是显式的实验能力，并会随工程范式演进保持灵活性。

Zero Trust Is the Security Boundary以零信任构筑真正的安全边界

An Agent is untrusted at every step. A system prompt, API contract, Tool description, model safety policy, Channel membership, hidden navigation item, or Graph projection can guide behavior, but none can authorize access. Every read, disclosure, model call, Skill/Tool/API acquisition, side effect, memory promotion, artifact transfer, and commit must resolve an authenticated Principal and re-evaluate current server-side authorization. Missing or stale identity, policy, purpose, scope, or validity fails closed.任何时刻都不默认信任Agent。 系统提示词、API规范、工具描述、模型安全策略、频道成员关系、前端菜单隐藏或图投影都只能引导行为，不能授予权限。每次读取、披露、模型调用、技能/工具/API获取、副作用、记忆提升、制品传输与结果提交，都必须解析已认证主体并重新校验服务端当前授权；身份、策略、用途、范围或有效期缺失、失效、过期时一律拒绝。

Credential Protection凭证保护

Encryption Supports Zero Trust以加密支撑零信任执行

Encryption protects secrets at rest and during controlled distribution, but encryption alone is not authorization. Chuanxu combines independent Agent key material, encrypted runtime configuration, rotation, dedicated database identities, short-lived instance credentials, and current policy checks to constrain the impact of credential or Agent compromise.加密保护静态存储和受控分发中的秘密，但加密本身不等于授权。川序将Agent独立密钥材料、运行配置加密、密钥轮换、独立数据库身份、短期实例凭证与当前策略校验结合，用于限制凭证或Agent受损后的影响范围。

Per-Agent Crypto Keys每Agent加密密钥
Each Agent receives its own 256-bit encryption key at registration, stored in SYSTEM_CONFIG, distributed via admin_token-authenticated channel. Compromise is scoped to a single Agent with instant key rotation.每个Agent注册时获得独立的256位加密密钥，存储于SYSTEM_CONFIG，通过admin_token认证通道分发。攻击面限制在单一Agent，支持即时密钥轮换。
Auto-Encrypt at Rest启动时自动加密
Server startup encrypts database credentials, LLM and model-routing API keys, and the session-signing secret with AES-256-GCM. config.json and master.key are always restricted to owner-only (0600) access.服务器启动时使用AES-256-GCM加密数据库凭证、LLM与模型路由API Key以及会话签名密钥。config.json与master.key始终限制为仅所有者可读写（0600）。

5-Signal Unified Hybrid Search5信号统一混合搜索
A single SQL CTE query fuses 5 search signals: vector similarity (configurable embedding model), BM25 full-text with Oracle Text / PG ts_vector / YashanDB SEARCH INDEX, relational category/domain/importance filters, tag-based matching, and graph traversal (CAUSES/RELATED/neighbors). Only the top-N ranked results enter the LLM prompt — minimizing context window bloat. The system auto-detects the optimal strategy based on query characteristics, with a unified API endpoint that keeps LLM token consumption minimal regardless of query type.单SQL CTE查询融合5种搜索信号：向量相似度（可配置嵌入模型）、BM25全文检索、关系型类别/领域/重要性过滤、标签匹配、图遍历。仅Top-N排序结果进入LLM prompt——减少上下文窗口膨胀。系统根据查询特征自动检测最优策略，统一API端点确保无论查询类型如何，LLM token消耗最小。
Database-Native Vector Storage数据库内向量存储
Memories and knowledge are stored as structured entities with database-native vector embeddings (Oracle AI Vector Search / PG pgvector / YashanDB VECTOR). Full text content is preserved alongside vectors, enabling both semantic and keyword retrieval. Typed edges (PROMOTED_TO, DERIVED_FROM, MERGED_INTO) connect related entities — the LLM receives curated, context-rich summaries rather than raw data dumps.记忆和知识以结构化实体存储，数据库中同时保留全文内容和向量嵌入。类型化边(PROMOTED_TO, DERIVED_FROM, MERGED_INTO)连接相关实体——LLM接收精选的上下文丰富摘要，而非原始数据转储。
Knowledge Extraction & Consolidation知识提取与整合
Auto-extract knowledge from memory clusters via EXTRACTED_FROM edges. The system periodically consolidates multiple related memories into a single knowledge entity — reducing future context requirements by orders of magnitude. Context branching avoids redundant re-processing of unchanged data across sessions.通过EXTRACTED_FROM边从记忆簇中自动提取知识。系统定期将多条相关联记忆整合为单一知识实体——将未来的上下文需求降低数个数量级。上下文分支避免跨会话对未变更数据的重复处理。

PostgreSQL Implementation NotesPostgreSQL 实现说明
The PostgreSQL 18 edition keeps the portable relational runtime as the execution authority and uses Apache AGE as its Property Graph projection. RLS provides per-agent row-level isolation; PL/Python3u replaces UTL_HTTP for outbound HTTP calls; pg_cron replaces DBMS_SCHEDULER; pgvector replaces Oracle VECTOR; and tsvector/tsquery replaces Oracle Text. YashanDB Implementation Notes崖山数据库实现说明
The YashanDB 23.5.4+ edition uses its native Property Graph projection for graph-facing operations while the shared relational Graph runtime remains the durable execution authority. Role-Based Access Control (GRANT/REVOKE + DEFINER packages) provides isolation; yaspy provides Python connectivity; SEARCH INDEX and VECTOR + HNSW provide retrieval; DBMS_SCHEDULER handles jobs; LIST partitioning and native JSON conversion support the portable schema; and the built-in crypto package protects database-held secrets.YashanDB 23.5.4+版本使用原生Property Graph投影承载面向图的操作，同时以共享关系型Graph运行时作为持久化执行权威。角色权限控制（GRANT/REVOKE + DEFINER包）提供隔离；yaspy负责Python连接；SEARCH INDEX与VECTOR + HNSW提供检索；DBMS_SCHEDULER处理调度作业；LIST分区与原生JSON转换支持可移植Schema；内置加密包保护数据库内敏感数据。
