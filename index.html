Agent 从 POC 进入生产，关键不再只是模型能力，而是状态能否恢复、过程能否审计、权限能否治理。川序是基于数据库的 AI Agent 管理平台，统一管理已注册 Agent 的身份、权限、组织归属、任务、协作、运行状态与审计证据，让企业中的 Agent 可观测、可调度、可运维。平台账号、组织人员与 Agent 责任关系以数据库事实对齐；不同框架中的 Agent 通过 Skill 等受控接口接入，核心状态在异常后可由替代实例恢复。As Agents move from POC to production, the critical questions are no longer only about model capability, but whether state can recover, execution can be audited, and authority can be governed. Chuanxu is a database-native AI Agent management platform. It unifies identity, authorization, organization ownership, tasks, collaboration, runtime state, and audit evidence for registered Agents, making enterprise Agents observable, schedulable, and operable. Platform accounts, organization people, and Agent accountability align as database facts; Agents from different frameworks connect through controlled interfaces such as Skills, and replacement instances can recover core managed state after failure.

让 A2A 与 DB4A2A 共享同一条可追溯任务链Give A2A and DB4A2A One Traceable Task Chain

v4.5.2 将标准 A2A 与数据库介导的 DB4A2A 派发关联到同一数据库任务根，复用任务计划、步骤、上下文、协作关卡、图投影、Outbox 和审计实体，并对幂等、租约、围栏令牌与未知发送结果进行统一治理。v4.5.2 binds standard A2A and database-mediated DB4A2A dispatches to one database task root, reusing Task Plans, Steps, context, collaboration gates, graph projections, Outbox, and audit entities with one contract for idempotency, leases, fencing, and unknown-send recovery.

CANONICAL TASK ROOT

数据库任务计划复用Reuse the Database Task Plan

A2A、DB4A2A 和多步骤 MCP 工作统一落到稳定任务 ID、步骤、租约和尝试记录。协议消息或模型输出不会自行创建权限，也不能绕过已有的任务计划与审批边界。A2A, DB4A2A, and multi-step MCP work share stable task IDs, Steps, leases, and attempt records. Protocol messages and model output never create authority or bypass existing Task Plan and approval boundaries.

DB4A2A

数据库介导的引用协作Database-mediated Reference Collaboration

任务分发时传递受治理的上下文引用，而不是在 Agent 之间复制大体量数据；接收方只读取当前授权范围，并可建立带来源、父分支和完整流向的工作分支。DB4A2A 是平台内数据库介导协作，不等同于默认关闭、需单独验证边界的跨组织 A2A 协议。Task delegation passes governed context references instead of copying large payloads between Agents. A recipient reads only its current authorized scope and may create a work branch with source, parent, and full-flow provenance. DB4A2A is database-mediated collaboration inside the platform; it is distinct from cross-organization A2A protocol support, which remains disabled by default and requires independent boundary validation.

安全边界Security Boundary

Agent 运行安全不能依靠提示词Agent Security Cannot Depend on Prompts

提示词、API 规范、模型策略、频道成员关系和前端菜单只能表达意图，不能授予权限。川序在服务端按当前身份、归属、角色、显式拒绝、安全域、用途、密级和有效期重新决策。Prompts, API contracts, model policies, channel membership, and visible menus express intent but never grant authority. Chuanxu re-evaluates identity, ownership, roles, explicit deny, security domain, purpose, classification, and validity server-side.

  • 身份、授权或凭证缺失、失效、过期时失败关闭Fail closed when identity, grants, or credentials are missing, stale, or expired
  • 高风险访问支持多人审批、职责分离和即时撤销High-risk access supports multi-party approval, separation of duties, and immediate revocation
  • 同一 Agent 可按安全域、频道或任务隔离实例与短期凭证Isolate instances and short-lived credentials by security domain, channel, or task

Effective capability is the intersection of the package, database capability matrix, runtime configuration, and subject authorization.

图能力矩阵GRAPH CAPABILITY MATRIX

受控与禁用能力Controlled and Disabled Capabilities

Graph Runtime 核心与授权检查属于稳定生产基线。草稿导入、SLO 只读检查与检查点分叉独立受控；已登记 MCP、A2A、仅元数据遥测和固定隔离框架按各自授权启用。离线回放与迁移预检只分析持久事实，真实副作用回放、运行中迁移、任意框架执行与全局自治保持关闭。Graph Runtime core and authorized inspection remain available. Draft import, read-only SLO views and checkpoint forks are independently controlled. Registered MCP, bounded A2A, metadata-only telemetry and one pinned isolated framework use separate authorization. Offline replay and migration preflight inspect persisted facts; live effect replay, live migration, arbitrary frameworks and global autonomy remain disabled.
