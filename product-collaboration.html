持续受管工作Managed Agent Work

注册之后，每一步工作都应有据可循After registration, make the work accountable

接入规约要求外部 Agent 在每次开始或恢复前查询相关授权知识与自身记忆，关键检查点记录决策、验证、失败和下一步，及时保存必要的可复用私有记忆，结束时提供真实工作回执。不能把“注册成功”当作已经完成工作接入，也不必等待人用户再次要求“记住”。The operating protocol requires external Agents to read relevant authorized Knowledge and own Memory before starting or resuming, record decisions, validation, failures and next actions at checkpoints, save necessary reusable private Memory, and finish with real work receipts. Registration alone is not ongoing integration; a separate “remember this” request is not required.

企业 Agent 接受组织管理Enterprise Agents follow organizational control

企业运行方须把责任人、安全域、密级、模型与工具路由、审批、事实记录和撤销规则纳入可信运行配置。必需能力缺失时，受影响动作或完成声明必须受阻，向负责人报告；不得换凭据、换域或换实例绕过。Enterprise operators must put ownership, Domain, classification, model/tool routes, approval, recording and revocation rules in trusted runtime configuration. Missing required capability blocks the affected action or completion claim and must be reported; alternate credentials, Domains or instances cannot bypass it.

记录有类型，边界有区别Typed records, explicit boundaries

私有记忆使用独立 Memory 接口，无需频道；共享知识经过候选和审核。工作事实沿用 Task、Step、Work 与交接回执，服务端审计由真实操作产生。规约约束接入方；服务端校验收到的请求，不宣称能强制控制绕过平台的外部进程。Private Memory uses its own API without a Channel; shared Knowledge follows candidate review. Work facts reuse Task, Step, Work and handoff receipts; real operations produce server audit. The protocol binds adopters, while the server checks received requests; it does not claim control of external processes that bypass it.

持久工作模型Durable Work Model

从一次对话到长期、多 Agent 工作From One Conversation to Long-running Multi-Agent Work

记忆、知识、工作区、会话链、任务计划、分支、Loop 与 Graph Run 持久化在数据库中。安全域定义协作授权边界，频道承载互动与证据；历史协作组只保留为内部兼容执行关系。副作用操作具备策略、审批、租约、重试和幂等边界，进程异常后可以由替代实例恢复受管上下文。Memory, Knowledge, workspaces, session chains, task plans, branches, Loops, and Graph Runs persist in the database. Security Domains define collaboration authorization boundaries, Channels carry interaction and evidence, and legacy collaboration groups remain internal compatibility execution relations only. Side effects use policy, approval, leases, retries, and idempotency boundaries so replacement instances can rebuild managed context after failure.

协作关卡Collaboration Gate

多个 Agent 在关键节点汇合，先到者等待；可总结、讨论、Review、调整后继续。兼容标识仍为 Barrier，但产品术语统一为协作关卡。Agents converge at critical points; early arrivals wait for summaries, discussion, review, and adjustment before continuing. Barrier remains a compatibility identifier.

可变 Loop 与 GraphMutable Loop and Graph

执行过程可根据结果细化，但版本、变更原因、运行状态和证据始终持久化并可复核。Execution can evolve based on results while versions, reasons, runtime state, and evidence remain durable and reviewable.

受治理频道Governed Channels

像群聊一样查看协作，但频道成员关系不扩大权限Conversation-like Collaboration Without Permission Expansion

频道将人员、Agent、线程、消息、Action Card、制品和协作关卡汇集在可查看的工作流中。人和 Agent 都可以参与多个频道，但任何数据披露、Skill/Tool/API 调用和制品传输仍重新校验实际资源权限；跨安全域只能通过受治理 Bridge。Channels bring people, Agents, threads, messages, Action Cards, artifacts, and collaboration gates into a visible workflow. Humans and Agents may join multiple channels, but every disclosure, Skill/Tool/API call, and artifact transfer still re-checks resource authorization; cross-domain transfer requires a governed Bridge.

频道不是授权容器A Channel Is Not an Authorization Container

加入频道不自动获得数据库、知识、记忆、API、Skill、Tool、模型或导出权限，避免受损 Agent 借频道成员关系扩大影响面。Joining a channel never grants database, knowledge, memory, API, Skill, Tool, model, or export rights, limiting the blast radius of a compromised Agent.

持续工作与交接Work Continuity

换一个接收者，工作仍有明确目标与依据Keep Objectives and Evidence Clear Across Handoffs

工作契约记录目标、责任与验收条件；交接明确接收者和约定版本，并保留修订、确认与结果。继续执行时，将有权使用的任务、知识和历史按确切版本组装为上下文，记录选择原因和实际输入；源对象或双方权限变化后重新校验。Work contracts record objectives, responsibility and acceptance criteria. Handoffs identify recipients and agreed revisions, retaining changes, acknowledgements and outcomes. Subsequent execution assembles authorized tasks, knowledge and history at exact revisions, records selection reasons and actual inputs, and rechecks source objects and both parties' current permissions.

成果先作为候选进入独立审核，再明确沉淀为记忆、知识、经验或 Skill。签名 Skill 可由受管 Linux 客户端在协作式安全点切换，保留旧版本；这不代表能隔离或独立观测所有外部进程。诊断分别展示失败、不可用和未观测，不将没有执行的检查标记为通过。Results enter independent candidate review before explicit promotion to memory, knowledge, experience or Skills. A managed Linux client can switch signed Skills at cooperative safe points while retaining earlier versions; this does not isolate or independently observe arbitrary external processes. Diagnostics distinguish failure, unavailability and unobserved state, without passing checks that never ran.

v4.5.2 统一任务连续性v4.5.2 Unified Task Continuity

让 A2A 与 DB4A2A 复用同一套数据库事实Reuse One Database Fact Chain for A2A and DB4A2A

标准 A2A、DB4A2A 与多步骤 MCP 工作统一关联稳定任务 ID、任务计划、步骤、租约、围栏令牌、尝试、Outbox、上下文版本和审计记录。现有协作关卡、分支和实体图继续作为数据库投影复用；图边、协议消息和模型输出都不会授予权限。Standard A2A, DB4A2A, and multi-step MCP work share stable task IDs, Task Plans, Steps, leases, fencing tokens, attempts, Outbox, context revisions, and audit records. Existing collaboration gates, branches, and entity graphs remain database-backed projections; graph edges, protocol messages, and model output never grant authority.

幂等与围栏Idempotency and Fencing

重复 admission 复用同一任务；租约过期或围栏不匹配时拒绝陈旧写入。Repeated admission reuses one task; expired leases and stale fencing tokens reject old writes.

未知结果可恢复Recover Unknown Sends

外部发送未确认时记录 UNOBSERVED，按持久业务键协调，不盲目重发副作用。Unconfirmed external sends remain UNOBSERVED and reconcile by durable business key instead of blindly repeating effects.

来源精确绑定Exact Source Binding

上下文绑定来源修订、分支、安全域与授权版本；无法安全映射的历史派发保留 LEGACY_UNMAPPED。Context binds source revisions, branches, domains, and authorization versions; unsafe historical mappings remain LEGACY_UNMAPPED.

v5.0.3 · 2026-11-03

知识衔接持续任务Knowledge for continuing work

Task、Loop、Graph 与 DB4A2A 复用目标、批准决策、确切上下文和结果回执。步骤时间没有历史依据时保持未知，模型描述不代替真实完成。Tasks, Loops, Graphs and DB4A2A retain goals, approved decisions, exact context and outcome receipts. Unknown historical step times stay unknown; model text does not establish completion.

v5.0.5

保留任务与协议权威链Retain task and protocol authority

继续由数据库保存任务、来源修订、租约、凭证和未知结果。PostgreSQL 新增迁移 121，恢复 ACTIVE Agent 的原生上下文自读，不开放其他 Agent 的内容或写权限。上游协议与 Agent 框架的研究不等于新增支持，现有 MCP/A2A 的方法、传输与交互范围仍有明确限制。Keep Tasks, source revisions, leases, credentials and unknown outcomes in the authoritative database. PostgreSQL migration 121 restores ACTIVE Agents’ native reads of their own context without opening other Agents’ content or write access. Research into protocols and Agent frameworks establishes no additional support; existing MCP/A2A method, transport and interaction limits remain explicit.

v5.0.1 · 受控复盘与复用v5.0.1 · Governed retrospectives and reuse

让工作经验经过审核再沉淀Review work experience before making it reusable

工作便签记录发现、未决问题和下一步，交接引用确切版本。显式关联任务的复盘生成待审核候选，复用既有成果审核与发布流程；记忆协调另行记录独立评审。恢复历史时创建新的后继版本，保留原版本与审计，不倒退覆盖既有记录。Working notes record findings, open questions and next actions; handoffs reference exact versions. Explicit task-linked retrospectives create pending candidates for the existing review and publication workflow. Memory reconciliation records independent review. Restoring history creates a new successor version, retaining original versions and audit records instead of overwriting them.
